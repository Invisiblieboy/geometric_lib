# План тестирования geometric_lib

Лабораторная работа №4 «Написание unit-тестов».
Исходный код тестов — в каталоге [`tests/`](tests/), запуск из корня репозитория:

```
python -m unittest -v
```

## 1. Цели и задачи тестирования

**Цель:** проверить, что функции вычисления геометрических величин возвращают значения, соответствующие формулам, и выяснить, как они ведут себя на некорректных входных данных.

**Задачи:**

- разработать unit-тесты на `unittest` для всех четырёх модулей;
- проверить каждую функцию на положительном размере, на граничном значении 0 и на отрицательном размере;
- зафиксировать фактические результаты и описать найденные дефекты.

## 2. Описание тестируемого продукта

Библиотека из четырёх модулей, каждый содержит функции вычисления величин одной фигуры. Функции принимают размеры (`int | float`) и возвращают число.

| Модуль | Функция | Назначение | Ожидаемое значение |
|---|---|---|---|
| `circle.py` | `area(r)` | площадь круга | π·r² |
| `circle.py` | `perimeter(r)` | длина окружности | 2·π·r |
| `square.py` | `area(a)` | площадь квадрата | a² |
| `square.py` | `perimeter(a)` | периметр квадрата | 4·a |
| `triangle.py` | `area(a, h)` | площадь треугольника по основанию и высоте | a·h / 2 |
| `triangle.py` | `perimeter(a)` | периметр правильного треугольника | 3·a |
| `cube.py` | `area(a)` | площадь поверхности куба | 6·a² |
| `cube.py` | `volume(a)` | объём куба | a³ |

Для `circle.py` и `square.py` формулы взяты из docstring'ов. У `triangle.py` и `cube.py` документации нет, поэтому ожидаемое поведение определено по названиям функций и параметров. Поведение на некорректных данных не описано ни в одном модуле.

## 3. Область тестирования

**Входит:** все 8 функций четырёх модулей, перечисленные в разделе 2.

**Не входит:** производительность, безопасность, интеграция с другими модулями, входные данные нечисловых типов.

## 4. Стратегия тестирования

- **Уровень:** модульное (unit) тестирование.
- **Метод:** чёрный ящик. Тесты написаны по контракту функций (формулам из раздела 2), исходный код модулей не изменялся.
- **Техники:** разбиение на классы эквивалентности (положительный размер, ноль, отрицательный размер), проверка граничного значения 0.
- **Инструменты:** `unittest`. `assertEqual` — для целочисленных результатов, `assertAlmostEqual` — для результатов с π, `assertRaises` в форме контекстного менеджера — для некорректных данных.
- **Принятое требование:** при отрицательном размере функция должна выбрасывать `ValueError`. В документации это не указано; требование принято, так как отрицательная длина стороны или радиуса не имеет геометрического смысла.
- **Организация:** один файл `tests/test_<модуль>.py` и один класс-наследник `unittest.TestCase` на каждый модуль.

## 5. Критерии приёмки

- Все тесты выполняются без статуса ERROR, то есть каждый тест корректен и отработал до конца.
- Каждая функция покрыта как минимум тремя тестами: положительный размер, ноль, отрицательный размер.
- Продукт принимается, если все тесты завершились со статусом `ok`. Каждый FAIL считается дефектом продукта и фиксируется в разделе 7.

## 7. Актуальные результаты тестирования

Выполнено 25 тестов: **17 ok, 8 FAIL, 0 ERROR** (пройдено 68 %). Все 8 функций покрыты тестами.

Все проваленные тесты завершились с `AssertionError: ValueError not raised`. Фактически функции вернули:

| Вызов | Фактический результат |
|---|---|
| `circle.area(-20)` | 1256.637 |
| `circle.perimeter(-20)` | −125.664 |
| `square.area(-1)` | 1 |
| `square.perimeter(-10)` | −40 |
| `triangle.area(1, -1)` | −0.5 |
| `triangle.perimeter(-10)` | −30 |
| `cube.area(-1)` | 6 |
| `cube.volume(-10)` | −1000 |

**Дефект D1.** Ни одна функция не проверяет входные данные: отрицательные размеры принимаются без ошибки во всех четырёх модулях.

## 8. Выводы из результатов тестирования

- На корректных данных (положительный размер и ноль) все четыре модуля вычисляют значения по формулам: 17 тестов из 17 пройдены.
- Все 8 провалов вызваны одним дефектом D1: отсутствием проверки входных данных. Опасность в том, что ошибка не видна снаружи. Периметр и объём получаются отрицательными, а площади круга, квадрата и куба выглядят правдоподобно (`square.area(-1) = 1`), поэтому неверный ввод может пройти незамеченным.
- По критериям раздела 5 продукт не принимается. Рекомендация разработчику: добавить в функции проверку `if a < 0: raise ValueError(...)` и описать поведение на некорректных данных в документации.
- У `triangle.py` и `cube.py` нет документации, поэтому их ожидаемое поведение пришлось определять по названиям функций. Это стоит исправить вместе с D1.
